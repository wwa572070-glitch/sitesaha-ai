# 人工录入标准（JGJ 与 GB 50xxx 系列）

## 为什么需要这个目录

项目只通过 `scripts/fetch_public_standards.py` 的合规通道采集标准。这条通道有两个硬边界：

| 通道 | 覆盖范围 | 现状 |
| --- | --- | --- |
| 国家标准全文公开系统（OpenStd） | **只收国家标准（GB / GB-T）** | 已采集 28 部元数据 |
| 济南市住建局公开附件 | 该局公开的附件 | 已取得 JGJ59-2011 全文 |

因此**以下两类标准无法自动采集**，需要人工按合法渠道取得后录入：

- **行业标准**：`JGJ 46-2005`（临电）、`JGJ 80-2016`（高处作业）、`JGJ 130-2011`（扣件式脚手架）、
  `JGJ 128-2010`（门式脚手架）、`JGJ 33-2012`（建筑机械）、`JGJ 147-2016`（拆除工程）
- **工程建设标准**：`GB 55034-2022`、`GB 50720-2011`、`GB 50194-2014`、`GB 50870-2013`

完整缺口清单与官方查询入口见 `data/sources/PENDING_STANDARDS.md`。

## 完整录入流程

### 第 1 步：取得合法文本

必须是有权使用的正式文本：项目已购买的标准、企业标准化资料库、或官方公开发布件。
**不要用来源不明的电子版**，公开可下载不等于可以任意再分发。

### 第 2 步：按模板填写

复制 `TEMPLATE.md` 为 `<标准编号> <标准名称>.md`，逐项填写。模板里 `TEMPLATE-` 开头的
都是占位符，必须全部替换。

**结构约束（写错会导致入库后无法检索）**：

- 第一个一级标题必须是 `# 标准编号 标准名称` 格式 —— 知识库用它作为文档标题
- 元数据用 `> 字段：值` 的引用行，字段名不能改
- 正文按 `##` / `###` 分节 —— 切片器按标题分段，段太长会影响检索精度

### 第 3 步：过校验

```powershell
python docs/standards-intake/check_intake.py
# 或指定文件
python docs/standards-intake/check_intake.py "docs/standards-intake/JGJ 46-2005 施工现场临时用电安全技术规范.md"
```

校验会拦下 8 类问题：

1. `TEMPLATE-` 占位符残留
2. 标题格式不对（编号解析失败或名称过短）
3. 缺少必备元数据行（状态 / 版本与实施日期 / 来源 / 来源链接 / 采集时间 / 授权说明）
4. **状态不是「现行」或「即将实施」**——已废止或被替代的标准不许录入
5. 缺少必需小节（适用范围 / 新工人需要记住的要点 / 免责说明）
6. 免责说明没写明「不能替代正式标准文本」
7. 没写明授权或取得渠道
8. **出现推测性表述**（「应该是」「大概」「根据经验」「通常规定为…」「待补」等）
   —— 标准条款不允许猜测或用惯例补全

> 下划线开头的文件（`_self_test_*.md`）是脚本自测样例，默认扫描时会跳过。

### 第 4 步：入库并重建索引

```powershell
# 1) 移到正式目录
New-Item -ItemType Directory -Force -Path data\sources\normalized\manual
Move-Item "docs\standards-intake\<你的文件>.md" data\sources\normalized\manual\

# 2) 重建索引前必须先停掉正在运行的服务，否则 SQLite 被占用会报
#    sqlite3.OperationalError: unable to open database file
python scripts/init_db.py --reset
```

`--reset` 会删除并重建数据库。**这一步是必需的**：不带 `--reset` 时
`seed_default_knowledge()` 发现库非空就直接返回，新文件不会入库。
索引是启动时从 Markdown 重建的，所以 `data/sitesaha.db` 不进版本库也不影响。

### 第 5 步：核对

```powershell
python docs/ui-build/verify_standards.py     # 标准数据自洽性
python webapp.py --port 8504                 # 另开终端
# 访问 /api/status，核对 documents / chunks 增长
```

预期：每部标准约增加 1 个文档、2-4 个片段（取决于分节数量）。

## 合规红线

- **不绕过**验证码、登录、付费墙或其他访问控制
- 取不到全文的标准**只登记元数据**，不用推测内容补全条款
- 录入的文件只用于本项目内部培训，**不代表获得再分发授权**
- 比赛提交、公开发布或商业部署前，需再次核对标准版权、来源网站条款与项目授权范围

## 免责

本条链路产出的是**培训用摘录**，不是标准的完整替代品。实际使用以正式发布的标准文本为准；
涉及高后果安全决策时，必须由现场安全员、项目技术负责人和作业许可流程确认。
